# Security Audit and Remediation — 2026-08-31

## Severity legend

- **Critical** — direct privilege escalation or payment forgery.
- **High** — account/tenant compromise, server-side request abuse, duplicate externally visible side effects.
- **Medium** — constrained data exposure, quota bypass, or availability/integrity risk.

## Findings

### 1. Better Auth additional-field mass assignment — Critical

- **Location:** `apps/backend/src/lib/auth.ts:83-107`
- **Root cause:** server-owned fields are exposed as Better Auth `additionalFields` without `input: false`.
- **Exploit scenario:** a public sign-up or authenticated update-user request supplies `role: "ADMIN"` or other entitlement/channel fields.
- **Fix applied:** pending.

### 2. Unsigned Duitku SNAP callback and payment TOCTOU — Critical

- **Location:** `apps/backend/src/services/duitku-service.ts:400-430`, `apps/backend/src/services/payment-service.ts:487-678`
- **Root cause:** `partnerReferenceNo` is trusted without cryptographic verification; payment status and subscription activation are separate unconditional writes.
- **Exploit scenario:** a forged callback marks a known order completed; duplicate callback/poll/cancel paths race and produce inconsistent payment and entitlement state.
- **Fix applied:** pending.

### 3. Turnstile/2FA bypass — High

- **Location:** frontend login/register forms, `apps/backend/src/routes/turnstile.ts`, `apps/backend/src/routes/auth.ts:167-188`
- **Root cause:** Turnstile is checked only in UI and its token is not sent with auth requests; legacy 2FA verifies presence rather than validity.
- **Exploit scenario:** direct HTTP clients bypass Turnstile; any non-empty 2FA token passes legacy login.
- **Fix applied:** pending.

### 4. Active-content upload and webhook SSRF — High

- **Location:** `apps/backend/src/routes/media.ts`, `apps/backend/src/services/webhook-service.ts`, `apps/backend/src/workers/webhookOutboundWorker.ts`
- **Root cause:** upload extension is client-controlled while MIME is trusted; webhook URL validation checks only scheme and fetch follows redirects.
- **Exploit scenario:** authenticated upload serves executable HTML from the API origin; webhook delivery reaches loopback/private/link-local services.
- **Fix applied:** pending.

### 5. Tenant isolation gaps — High

- **Location:** `apps/backend/src/routes/messages/send.ts:199-230`, generic media routes, global WhatsApp client factory.
- **Root cause:** customer lookup is not scoped by tenant; media accepts a caller-provided phone-number ID; global credentials are used across tenant operations.
- **Exploit scenario:** a known foreign customer/media identifier is used for cross-tenant side effects.
- **Fix applied:** pending.

### 6. Rate-limit trust and route ordering — High

- **Location:** `apps/backend/src/index.ts:167-188`, rate-limit and API-key middleware.
- **Root cause:** handlers are registered before some limiters and raw forwarded headers are trusted as client identity.
- **Exploit scenario:** direct callers rotate `X-Forwarded-For` or use an unguarded auth path.
- **Fix applied:** pending.

### 7. Concurrency races — High/Medium

- **Location:** OTP service, bulk send service, invitation service, quota checks, and cron startup.
- **Root cause:** read-check-write sequences do not use CAS, transactions, or distributed locks.
- **Exploit scenario:** parallel guesses bypass OTP attempt limits; bulk recipients receive duplicates; invitations/quota exceed limits; every replica runs cron side effects.
- **Fix applied:** pending.

### 8. Secondary data/dependency hygiene — Medium

- **Location:** monitoring routes, CSV export, Instagram webhook logging, workspace manifests.
- **Root cause:** caller-selected user IDs, unsafe CSV serialization, raw sensitive logs, outdated dependencies, and obsolete `next lint` command.
- **Exploit scenario:** cross-tenant metrics exposure, spreadsheet formula execution, PII leakage, or known package vulnerabilities.
- **Fix applied:** pending.

## Operator actions

- Audit existing users for unauthorized `ADMIN` roles and suspicious changes to channel identifiers.
- Confirm the official Duitku callback mode in production and provision the required SNAP public-key/signature material if SNAP callbacks are enabled.
- Set and verify trusted reverse-proxy/CIDR configuration before production rollout.
- Prefer a separate cookieless upload/media origin; code hardening reduces risk but does not replace origin isolation.
- Rotate credentials if logs containing webhook signatures or raw sensitive payloads have left the host.
